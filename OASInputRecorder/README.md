# OAS 操作记录器（MuMu）

双击 **OASInputRecorder.exe** 即可使用，无需 Python，不会弹出命令行黑框。程序已预填当前 OAS 安装路径；移动 OAS 后请重新选择目录。

1. 启动记录器，状态显示“监测中”后运行 OAS；OAS 已在运行时也可直接接入。
2. 查看点击坐标、滑动/拖动起止坐标、时间、配置名、目标和调用耗时。
3. 点击列表中的记录可在 1280×720 坐标图中高亮；“载入截图底图”可加载模拟器游戏画面的截图，应使用不含窗口边框的 1280×720 图片。
4. 全部记录自动保存在 EXE 同目录的 `Records` 文件夹中，每次启动创建独立 CSV。也可点击“导出 CSV”另存。
5. “导入历史日志”用于查看以前的操作。导入时暂停实时记录，CSV 的“来源”列区分历史和实时。重复导入同一文件会重复添加记录。

## 记录范围

此版本只读 OAS 已有日志，不修改 OAS、MuMu 或游戏，不发送鼠标/触控输入，不要求重启 OAS。

- 读取 `log/YYYY-MM-DD_配置名.txt` 内 `control.py` 输出的操作完成日志，支持后台点击。
- 坐标和耗时来自 OAS 日志，不是从模拟器触摸设备采样。耗时是控制调用耗时，不等同于触摸保持时间。
- 滑动线连接日志中的起止点，仅作方向示意，**不包含真实逐帧轨迹**；后端可能对坐标做缩放或细微调整。
- 不记录手动鼠标点击，也不覆盖绕过公共控制入口且未写操作日志的任务。现有日志将部分长按也写为 `Click`，因此显示为“点击”。
- 已记录不代表游戏已响应；未完成、被丢弃或在输出日志前报错的操作不会显示。
- 当前监测不判断 MuMu 进程是否存活；若 OAS 没有输出新操作，界面会保持等待。
- 开始/恢复记录时从现有文件末尾开始，跨天的新日志从头读取。暂停期间的操作不会补录；需要时可手动导入历史文件。
- 界面表格保留最近 1,000 条，图中显示最近 250 条；CSV 保存本次全部已读取记录。
- 请在可写目录运行 EXE。默认保留原安装文件夹中的源码和构建脚本，但运行只需要 EXE。

## 验证

通过 11 组检查：坐标/时间/耗时解析、滑动起止点、过滤任务意图与 API 重复日志、异常输入、CSV 转义、文件增量读取、截断恢复、UTF-8 分段读取、点位图绘制、真实 OAS 日志解析、完整窗口构造与绘制。

已从本机 2026-09-16 的 OAS 日志识别 3,374 条操作，其中 12 条滑动/拖动。未启动游戏验证新的实时操作；当前测试使用已有日志及模拟追加日志。

源码：`Recorder.cs`。使用系统 .NET Framework 4.x；通过 `build.ps1` 重新生成 EXE。开发自检命令：`OASInputRecorder.exe --self-test test-results.txt`。
